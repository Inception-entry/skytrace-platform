# Evidence Center Phase 3 上线前闭环清单

> 适用范围：`phase 3` 归档、哈希回填、归档后清理、前端联调与压测上线准备。
>
> 当前状态判断：开发闭环已完成；生产上线闭环仍需按本清单逐项验收。
>
> 本文档更新时间：2026-08-11

## 1. 当前结论

当前代码已经具备以下能力：

- 证据归档任务创建、执行、查询和下载
- `contentHash` 新链路计算
- 历史哈希回填能力
- 归档后清理能力
- 前端管理入口
- 归档完整性校验
- 真实链路压测脚本

但这不等于“现在已经可无风险上线”。真正的上线闭环，还需要完成下面 4 个收口动作：

1. 先处理 Flyway 历史迁移校验漂移。
2. 再确认历史 `contentHash` 回填执行方案。
3. 再确认归档后清理策略与审批口径。
4. 最后完成真实环境联调与压测验收。

## 2. 必须完成

以下事项未完成前，不建议发布到生产环境。

### 2.1 Flyway 历史迁移校验收口

目标：生产环境必须能在不关闭 `validate` 的前提下正常发布。

当前已知风险：

- 本地历史库在本次开发前已经存在 `V10`、`V12`、`V14`、`V15` checksum 漂移。
- 本轮开发没有改写这些历史脚本，也没有对本地库执行 repair。
- 生产环境禁止照搬本地临时覆盖配置中的 `validate-on-migrate=false`。

上线前必须完成：

- [ ] 确认目标环境 `flyway_schema_history` 中 `V10/V12/V14/V15/V18` 均存在且 `success=1`
- [ ] 对目标环境做数据库备份
- [ ] 明确漂移原因是“历史脚本改过”还是“库元数据落后于仓库”
- [ ] 若需 repair，先在预发环境完整演练
- [ ] 生产执行 repair 或标准化迁移处理后，再次验证应用可正常启动
- [ ] 确认生产配置未关闭 Flyway `validate`

验收标准：

- 应用在生产配置下可直接启动
- 不依赖关闭 Flyway 校验
- `V18` 已成功落库

### 2.2 历史 `contentHash` 回填

目标：历史证据也具备与新链路相同的可追溯性。

上线前必须完成：

- [ ] 统计生产库 `content_hash` 为空的记录数
- [ ] 核对这些记录对应的 MinIO 对象是否存在
- [ ] 在预发环境用小批量验证回填
- [ ] 明确生产批次大小与重试策略
- [ ] 明确回填期间是否允许业务继续上传/归档
- [ ] 正式执行生产回填
- [ ] 回填后抽样核验哈希值

验收标准：

- 历史空哈希记录清零，或有书面豁免清单
- 回填失败记录可追踪，可重试

### 2.3 归档后清理策略确认

目标：把“技术上能删”变成“业务批准可以删”。

上线前必须完成：

- [ ] 明确哪些证据允许物理删除
- [ ] 明确保留天数
- [ ] 明确必须先软删除再进入清理
- [ ] 明确审批人、执行人、审计复核人
- [ ] 明确首次上线是否长期保持 `dry-run`
- [ ] 明确正式清理的灰度批次顺序：`1 -> 5 -> 10 -> 20`

验收标准：

- 有书面策略
- 有责任人
- 有异常恢复预案

### 2.4 真实环境联调与验收

目标：确保不是“代码能跑”，而是“业务能用”。

上线前必须完成：

- [ ] 前端页面可创建归档任务
- [ ] 用户可看到任务状态流转
- [ ] ZIP 与 manifest 可下载
- [ ] 下载链接有效期符合预期
- [ ] 角色权限符合真实模型
- [ ] 失败状态能被识别
- [ ] 恢复/重试路径有实际验证记录

验收标准：

- 至少完成一轮真实业务数据链路联调
- 前端、后端、产品对行为认知一致

## 3. 强烈建议完成

这些不一定阻塞上线，但不做会明显放大风险。

### 3.1 真实数据压测

重点覆盖：

- 单任务大量证据数量
- 大文件归档
- ZIP 打包耗时与内存
- MinIO 抖动或短时失败
- Temporal 重试与恢复
- 清理批处理吞吐量

验收标准：

- [x] 有压测记录
- [x] 有可接受阈值
- [x] 有失败样本和结论

当前本地实测记录：

- [x] 常规后端压测：20 个 4 MiB 文件，总计 80 MiB，归档与下载通过
- [x] 故障恢复压测：2 个 1 MiB 文件，MinIO 停止 10 秒后恢复，归档与下载通过
- [x] 两轮压测 `jobCode` 已留档：`AR-20260811-93CCD2`、`AR-20260811-FD1C5C`

## 5. 推荐执行顺序

建议严格按下面顺序推进：

1. 先处理 Flyway 历史迁移校验问题。
2. 再确认并执行历史 `contentHash` 回填。
3. 再确认归档后清理策略和审批口径。
4. 再做真实环境联调。
5. 再做真实数据压测。
6. 最后确认开关、上线窗口、回滚方案。
