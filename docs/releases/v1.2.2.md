# v1.2.2 发版说明

发布日期：2026-09-21（候选稿，随 RC 滚动）  
平台版本：`1.2.2`  
Git tag：**最新候选 `v1.2.2-rc.24`。不要直接打生产 `v1.2.2`**  
基于版本：`v1.2.1`

P0 热修补丁，以及后续合入的认证/上传/OIDC/供应链修正。  
**Flyway 增补 V21（`alarm_event.source_detection_id`），无 Prisma 迁移，无故意破坏性 API 变更。** 时间协议仍是上海 `DATETIME`，不是 UTC Instant。

## 现在该不该发生产

**不该。** 代码版本已对齐 `1.2.2`，候选打到 `v1.2.2-rc.24`。正式 `v1.2.2` tag 要等下面这些修完或书面豁免：

- detection outbox/DLQ、整栈回滚
- 操作日志历史数据清理、已部署 Keycloak 库内开发账号盘点（改 JSON 不会删旧用户）
- 已有 Keycloak 卷的 redirect/webOrigin 不会被 `--import-realm` 覆盖

## 版本策略

- 唯一对外版本号：`1.2.2`（SemVer **补丁**：安全/正确性，无功能增量）
- 所有子项目 `package.json` / `pom.xml` / `pyproject.toml`（含 `e2e/`）对齐为 `1.2.2`
- 生产部署仍用不可变镜像 tag `main-<SHA7>`，不要 `latest`
- **为何是 1.2.2 而不是 1.3.0：** 没有新能力、没有 Schema、没有把时间协议改成 UTC

## 已知限制

- 已部署 Keycloak 里若早已导入开发用户，本版不会自动删除，需运维禁用
- 已有 Keycloak 数据卷通常不会被 `--import-realm` 覆盖；OIDC redirect 需 fresh volume 或手工改 `skytrace-web`
- Admin 开发依赖 vitest mocker 未升
- Admin 头像仍走 multer 内存（上限小）
- 写不了 cgroup 的环境（本地 pytest）PDF 解析没有内存上限
- 证据遗留 API 的 `createdAt` 仍是 `LocalDateTime` 墙钟
- detection outbox/DLQ、整栈回滚未做；没有 `detectionId` 的旧消息重投仍会再插一行
- Admin 登录/刷新限流仍是进程内，跨副本 Redis 未做

## 升级注意

- 合入本文后在 `main` 打 **`v1.2.2-rc.24`**；**不要**在 RC 验收前打 `v1.2.2`
- 不要挪动 `v1.2.1` / `v1.2.0` / 已有 `v1.2.2-rc.*`
- 生产滚动等正式 tag：`IMAGE_TAG=main-<sha7> ./scripts/deploy-production.sh`
- 历史 `sys_operation_log` 仍可能有旧秘密，需只读扫描后再清理、轮换
- staging/production 必须给真实 hostname：`SKYTRACE_DOMAIN=test.example.com`（不要 `localhost`、不要带 `https://`）

## 验收建议

1. `python3 scripts/ci/assert_version_alignment.py`
2. `python3 scripts/keycloak/assert_realm_split.py`
3. `python3 scripts/ci/assert_staging_oidc_urls.py`
4. 证据详情：上海 `16:00` 墙钟应对应 `08:00Z`
5. `includeDeleted=false` 不返回已删证据
6. 知识库上传正常 PDF；损坏 PDF 仍失败；超页/超时必须 400；解析超时后子进程应退出
7. fresh 生产卷不应再出现 `skytrace-admin@local.test`
8. fresh 域名环境：登录 redirect / CORS / issuer 都是 `https://$SKYTRACE_DOMAIN`
9. Admin：无 refresh 的 401 能重新登录；登出后旧 refresh 不可再用
10. CI：`Trivy manifest scan (backend-ai)` 与 gateway 镜像扫描不再因 CVE-2026-63349 / CVE-2026-8763 / CVE-2026-71554 失败
11. 用 HTML 改扩展名为 `.jpg` 调证据/视觉上传必须 400；正常 JPEG/PDF 仍能过
12. 知识库/视觉上传正常文件仍能转到 AI；不要再走 `MultipartFile.getBytes()` 整份复制
13. 证据/知识库/视觉上传后 Node 临时文件应被删除；50MB 视频不应再整份进 BFF 堆
14. 畸形 PDF 把解析进程 RSS 打满时应 400「超出内存上限」，AI worker 不应被一起 OOM
15. 空 MySQL 只跑 Flyway（不要 init SQL）应能 `ddl-auto=validate` 启动，且有 `inspection_task`
16. 同一 `detectionId` 重投 detection 消息只落一条告警、只发一条实时通知；没有 ID 的旧消息仍可各插一行
