## 本版主要内容

### Sprint C

- 航线 CRUD（`inspection_route`）+ 任务可选 `routeCode`
- 视频抽帧流水线：`POST /api/detections/analyze-video`（ffmpeg → 逐帧检测 → 可选告警）
- AI 镜像默认安装 ffmpeg；真实 YOLO 通过 `docker-compose.vision.yml` 开启（CI 仍 mock）
- 业务端 `/routes` 航线页；任务表单可选航线

### Sprint D

- Grafana 预置 `SkyTrace Overview` 仪表盘
- Alertmanager 通过 `ALERTMANAGER_WEBHOOK_URL` 注入真实 webhook
- 新增 `docs/ops.md` 运维速查
- Playwright 入口冒烟（`e2e/`，验证 `/` 与 `/drone` 可达）

### 发版收口

- 全仓子项目版本对齐为 `0.3.0`
- Flyway `V6`（`uav_device` → `device`）与 `V8`（`inspection_task.route_code`）改为 Java 迁移，兼容 H2（本地/CI）与 MySQL（生产）
- 修复 Docker full-stack E2E：`inspection_route.waypoints_json` 实体与 MySQL `TEXT` 对齐，避免 Hibernate `validate` 导致 Java backend 无法启动
- 业务 MySQL 库由 `uav_inspection` 重命名为 `skytrace_inspection`（`MYSQL_DATABASE` / init / JDBC 默认值）

## 已知限制

- CI 默认仍不下载 YOLO 权重；真实推理需 vision overlay
- 视频抽帧依赖 ffmpeg；超长视频仅按 interval/maxFrames 采样
- 浏览器 E2E 未覆盖完整 Keycloak 登录与告警推送闭环
- 航线航点编辑仍为 JSON 文本，无地图可视化
- Temporal Nexus / 飞控独立服务仍未启动
- Keycloak realm / JWT 客户端等运行时契约仍保持 `uav` 兼容标识

## 升级注意

- 若环境已成功执行过旧版 **SQL** `V6`/`V8`，改为 Java 迁移后 checksum 会变化：对 `flyway_schema_history` 执行 repair，或重建数据卷后再启
- 已有环境改库名：将 `MYSQL_DATABASE` 设为 `skytrace_inspection`，迁移或重建业务库后重启 `backend-java`（Keycloak 库不受影响）
- 全新部署：按当前 `deploy/mysql/init` 与 `.env.example` 初始化即可

## 验收建议

1. `GET /api/routes` 有 `ROUTE-001`；创建任务时可绑定航线
2. mock 后端下图片分析仍可用；有 ffmpeg 时可测 analyze-video
3. monitoring overlay 后 Grafana 可见 SkyTrace Overview
4. 设置 `ALERTMANAGER_WEBHOOK_URL` 后 Alertmanager 配置含该 URL
5. `cd e2e && npm test`（需业务端已启动）
6. Docker profile 下 `backend-java` 健康检查 `/api/health` 可达；Compose full-stack CI 通过
7. 连接 MySQL 可见库名 `skytrace_inspection`，且含 `device` / `inspection_route` 等表
