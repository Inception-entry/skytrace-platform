# v1.0.0 发版说明

发布日期：2026-08-03  
平台版本：`1.0.0`  
Git tag：`v1.0.0`  
基于版本：`v0.3.0`

本版本达到仓库约定的 **生产可值守** 门槛：预发/生产真实 YOLO 默认可用、
浏览器 E2E 覆盖登录与告警/证据闭环并接入 CI、运维手册齐备。

品牌运行时已全面切换为 `skytrace`（Keycloak realm / JWT 客户端 / Java 包名 /
消息队列与存储命名等）；自历史 `uav*` 契约升级时需重建 Keycloak 数据卷或重新导入
`deploy/keycloak/skytrace-realm.json`，并清理旧 `uav-*` 容器后再拉栈。

## 版本策略

- 唯一对外版本号：`1.0.0`（SemVer 主版本）
- 所有子项目 `package.json` / `pom.xml` / `pyproject.toml`（含 `e2e/`）对齐为 `1.0.0`
- 容器镜像建议打 `1.0.0`，或与 CI `IMAGE_TAG` 并存

## 本版主要内容

### 真实 YOLO 生产路径

- Publish 对 `backend-ai` 构建参数 `INSTALL_VISION=1`（镜像内含 ultralytics）
- `deploy-staging.sh` / `deploy-production.sh` 强制挂载 `docker-compose.vision.yml`
- 预发/生产默认 `AI_VISION_BACKEND=yolo26`；本地/CI 仍可 mock

### 浏览器 E2E + CI

- Playwright：Keycloak 登录 → 创建/启动任务 → 上传证据 → 告警落库闭环
- Docker full-stack CI 启动 frontend，并在 API 验收后执行 `e2e` 套件

### 运维手册

- `docs/ops.md` 升级为 1.0 手册：备份/恢复、部署回滚、告警值班分级与升级路径

### 品牌运行时统一为 SkyTrace

- Keycloak realm / JWT audience与客户端、Compose 容器名、Java `groupId`/`package`
  由历史 `uav*` 全面迁移为 `skytrace*`
- 设备域编号（如 `UAV-001`）与类型 `UAV` 保留，不属于品牌残留

## 已知限制

- 航线航点仍为 JSON 文本编辑，无地图可视化
- Temporal Nexus / 独立飞控服务仍未启动
- 设备删除、DB status ↔ Redis 双向同步、证据分页/归档仍待后续
- 真实 YOLO 首次推理可能需下载权重（或预置模型）；CI 继续 mock

## 升级注意

- 自 `0.3.0` 升级：拉取新镜像后，预发/生产请使用更新后的 deploy 脚本（含 vision overlay）
- 若自建 Publish：确保 `backend-ai` 带 `INSTALL_VISION=1`，否则仅改 env 无法加载 ultralytics
- 业务库名仍为 `skytrace_inspection`（见 v0.3.0）
- 自仍使用 `uav` realm / `uav-web` 客户端的环境升级：必须切换到 `skytrace` /
  `skytrace-web`，并重建 Keycloak 导入卷；旧 Gateway/Frontend 镜像不可混用

## 验收建议

1. 预发/生产 `backend-ai` 环境变量 `AI_VISION_BACKEND=yolo26`，健康检查通过
2. `cd e2e && KEYCLOAK_DEV_USER_PASSWORD=... KEYCLOAK_CLIENT_SECRET=... npm test` 全绿
3. CI Docker full-stack 含 Playwright 步骤通过
4. 按 `docs/ops.md` 演练一次 MySQL 备份列出与回滚说明可读
5. 各子项目版本字段均为 `1.0.0`
